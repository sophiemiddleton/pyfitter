# ✂️ `cut_manager.py` - Cut Flow Management

The `cut_manager.py` module defines the `CutManager` class, responsible for systematically collecting, combining, and calculating statistics for all selection cuts applied during the analysis pipeline. It is essential for generating the standard **cut flow table**.

## 📝 `class CutManager`

### Initialization (`__init__`)

* Initializes `self.cuts` as an empty dictionary to store all defined cuts.
* Initializes a `Logger` instance for controlled output.

### Cut Definition and Toggling

#### `add_cut(self, name, description, mask, active=True)`

Registers a new cut into the manager.

* **`name`**: A unique string identifier for the cut.
* **`description`**: A human-readable summary of the cut logic.
* **`mask`**: The `awkward.Array` boolean mask generated by `analyze.py`, typically at the track level.
* **`active`**: Boolean flag determining if the cut is included in the final combined selection.

#### `get_cut_mask(self, name)`

Returns the `awkward.Array` boolean mask for a specific cut by name.

#### `toggle_cut(self, cut_names, active=False)`

Allows dynamic activation or deactivation of cuts after they have been defined, typically used to run the analysis with a subset of cuts enabled.

### Cut Combination

#### `combine_cuts(self, cut_names=None, active_only=True)`

This is the core function for generating the final selection mask used to filter the data.

* It iterates through the specified or active cuts and performs a logical **AND** operation (`&`) between their boolean masks.
* **Result:** Returns a single, combined `awkward.Array` mask that can be applied to the raw data to select only events/tracks that pass *all* active cuts.

## 📊 Cut Flow Statistics

### `calculate_cut_stats(self, data, progressive=True, active_only=True)`

Calculates the number of events remaining after each cut in the sequence.

* **`progressive=True` (Default):** Each cut is applied cumulatively on the results of all preceding cuts (sequential AND). This is the standard way to generate a cut flow table.
* **`progressive=False`:** Each cut is applied independently to the initial data sample.
* **The Masking Logic:** For track-level cuts (which operate on nested arrays of tracks per event), the final event count is determined using:
    $$\text{Events Passing} = \sum_{\text{event}} \text{ak.any}(\text{current-mask}_{\text{event}})$$
    This counts an event as "passing" if **at least one track** survives the applied `current_mask`.
* **Output:** Returns a list of dictionaries, where each dictionary contains the cut's name, description, event counts (`events_passing`), absolute efficiency, and relative efficiency.

### `print_cut_stats(self, data=None, stats=None, ...)`

Formats and prints the cut flow table to the console in a readable, aligned format.

* It can either calculate the stats on the fly (if `data` is provided) or print a pre-calculated list of statistics (if `stats` is provided).
* It also contains logic to optionally write the cut flow to a **CSV file**.

### `combine_cut_stats(self, stats_list, active_only=True)`

This critical function is used in `process.py` to aggregate results from parallel processing.

* **Input:** A list of cut statistics lists, where each inner list comes from a different file/worker.
* **Logic:** It sums the `events_passing` count for the same cut across all files/lists.
* **Recalculation:** After summing the raw event counts, it recalculates the **absolute** and **relative** efficiency percentages based on the new total event count. This ensures the final, combined cut flow table is accurate for the entire dataset.
